# ShutterClock — project context for Claude

Low-power BLE interval timer for fixed-point (time-lapse / phenology) cameras.
Triggers a Nikon DSLR through its wired remote terminal and optionally powers the
camera from a 12 V solar-charged battery. Sister project of SnowGauge.

## System (initial decisions)

- MCU: Seeed XIAO nRF52840 (non-Sense is enough), NCS v3.4.0 / Zephyr, Adafruit
  bootloader kept, no MCUboot, USB serial DFU only.
- Shutter: Nikon remote cable, 3 wires GND / AF / SHUTTER, MF lens. Two
  optocouplers (AF, SHUTTER), both off in sleep. Sequence: AF on → wait
  (camera wake, ~300–500 ms, tune on the real body) → SHUTTER on (~200 ms) →
  both off. Do not tie AF to GND permanently (keeps the camera half-pressed,
  meter never sleeps).
- Power in: 12 V lead-acid/LiFePO4 from a solar charge controller. Design every
  input-side part for ≥30 V (charging 14.8 V, PV open-circuit with battery
  disconnected). Fuse + TVS + P-MOSFET reverse protection (camera path ≥2 A).
- 3.3 V: low-Iq LDO rated ≥30 V in (SnowGauge's NJU7223 is only 14 V — not usable).
- Camera power: 9 V / ≥2 A buck module with EN (e.g. Pololu D36V28F9) on headers,
  feeding a Nikon dummy-battery coupler. EN from a GPIO with a jumper option for
  always-on. Optional current sense on the 9 V output (camera alive / card write
  finished). Decide always-on vs power-per-shot after measuring standby current.
- Battery monitor: gated divider, ADC node < 3.0 V at 30 V in.
- Schedule / BLE / SMP / Web Bluetooth page: same architecture and UI rules as
  SnowGauge (big buttons, pickers, two-tap destructive actions). BLE name
  `SC-XXXX`. Page at https://0kam.github.io/ShutterClock/app/.
- Records: one record per trigger (time, seq, flags, vbat, temp, camera current
  if fitted) → compare with EXIF times.

## Process (same as SnowGauge)

- Spec: `ShutterClock_設計仕様書_vX.Y.md` (Japanese, bump on every change).
- PCB generated by `pcb/generate_board.py` (KiCad 10 pcbnew); never hand-edit
  the .kicad_pcb; DRC via kicad-cli; gerber zip for JLCPCB; through-hole parts
  where possible (student assembly).
- Breadboard first with the real camera, measure (picowatt), then PCB;
  independent design review before every order.
- Chat in Japanese; code, comments, commit messages in English. The user places
  orders.

- Spec v0.4 lists the open items U1–U28 (§3) and the test-shot preview options

- **D7500 measured 2026-10-07, 4 runs** (`docs/measurements/2026-10-07_d7500_current.md`,
  9 V PSU → picowatt → EP-5B): standby = switch OFF = 0.42 mA (drifted down from
  0.60 mA after a clock reset); one shot 2.7 A·s with MF + standby timer 4 s
  (~85 % is the ~10 s awake after the shot); sensor cleaning only on power-switch
  ON/OFF; **supply restored with the switch ON → camera starts by itself, shutter
  fired 1.95 s after power-up with the remote held**; peaks 3–4.1 A, **PSU limit
  2 A → "Err"** → D36V28F9 too small, candidate D36V50F9 (U28). U8 leaning
  always-on (not decided by the user). picowatt can be driven from here:
  `cd ~/NIES/picowatt/app && uv run picowatt-cli --preset fast --adcrange 0 --cal`
  (port /dev/cu.usbmodem21401; analysis scripts are throwaway numpy, no pandas).
- **Target cameras (U1 closed)**: must work on D7200 and D7500; nice to have
  D7000, D7100, D800, D810. All six use EN-EL15-family batteries → one dummy
  battery type (EP-5B, 9 V like the EH-5b adapter). Release is the same 3 wires
  everywhere; only the camera connector differs (MC-DC2-type accessory terminal
  on the D7xxx, 10-pin on D800/D810: pin 4 release, 9 half-press, 6 signal GND).
  Proposed (U27): 3.5 mm stereo jack on the board + off-the-shelf 3.5 mm →
  MC-DC2 / 10-pin intervalometer cables. USB connector differs per body (spec §2.1).
- Pololu D36V28F9: EN has a 100 kΩ pull-up to VIN → never drive EN straight from
  a GPIO; use an open-drain N-MOSFET. Sleep draw ≈10–20 µA per volt of VIN.
- Camera clock runs from an internal rechargeable cell charged from the main
  battery/EP-5B; power-per-shot may let it run flat → candidate rule: ShutterClock
  records are the time reference, mapped 1:1 to file numbers (needs shot
  detection, U10).
- Preview idea under evaluation: Android Chrome + USB OTG cable to the camera,
  the same web page speaks PTP over WebUSB (no ShutterClock hardware). The user
  runs the no-code check on 2026-10-07 with the web-gphoto2 demo:
  `docs/measurements/2026-10-07_webusb_ptp_check.md` (procedure + result table).
